# Implementation Plan: Pipeline Server Integration for Document Generation

**Branch**: `002-pipeline-server-integration` | **Date**: 2025-10-05 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/002-pipeline-server-integration/spec.md`

## Summary

Deploy a dedicated OpenWebUI Pipelines server to enable DOCX, XLSX, and PPTX document generation without impacting the main BMS Agent search functionality. The Pipelines server runs as a managed background Python process on port 9099, hosts the `bms_document_generator` pipeline with function-calling tools for each document format, and integrates with OpenWebUI via connection configuration.

**Technical Approach**: Deploy Pipelines server from cloned repository in `/tmp/pipelines-repo`, install document generation dependencies (`python-docx`, `openpyxl`, `python-pptx`) within the pipeline environment, and provide deployment/testing scripts in `/workspace/001-bms-agent/pipelines/`.

## Technical Context

**Language/Version**: Python 3.11
**Primary Dependencies**: python-docx≥0.8.11, openpyxl≥3.1.0, python-pptx≥0.6.21, OpenWebUI Pipelines
**Storage**: Local filesystem under `/workspace/001-bms-agent/pipelines/output/`
**Testing**: Shell scripts (`test-document-generation.sh`), manual verification via curl
**Target Platform**: RunPod Linux server (Ubuntu), no Docker
**Project Type**: Backend service integration (single project)
**Performance Goals**: Document generation <10 seconds for standard documents (≤10 sections, ≤100 rows, ≤6 slides), server startup <2 minutes
**Constraints**: Localhost-only binding, default API key authentication (POC), no persistent storage (manual cleanup)
**Scale/Scope**: Single pod deployment, 3 document formats, ~300 LOC pipeline implementation

## Phase 0: Outline & Research

**Status**: ✅ Complete (M1 milestone reached - scripts and README committed)

### Research Areas Covered

1. **OpenWebUI Pipelines Architecture**
   - Decision: Use separate Pipelines server approach
   - Rationale: Avoids dependency conflicts with main OpenWebUI instance, allows isolated package installation
   - Alternatives considered: Marketplace tools (too limited), direct integration (dependency conflicts documented in `docs/openwebui-doc-gen.md`)

2. **Document Generation Libraries**
   - Decision: Use standard Python libraries (python-docx, openpyxl, python-pptx)
   - Rationale: Mature, well-documented, exact version requirements specified
   - Alternatives considered: ReportLab/FPDF2 for PDF (deferred to MVP), custom formats (unnecessary complexity)

3. **Process Management**
   - Decision: Use nohup with PID file tracking
   - Rationale: Simple, reliable, aligns with existing BMS Agent service management patterns
   - Alternatives considered: systemd service (overkill for POC), Docker (explicitly out of scope per spec)

4. **Output Storage Strategy**
   - Decision: Timestamped filenames in `/workspace/001-bms-agent/pipelines/output/`
   - Rationale: Prevents collisions, persists across restarts, manual cleanup workflow documented
   - Alternatives considered: Database storage (unnecessary), auto-cleanup (deferred to MVP)

**Output**: Findings documented above; existing implementation validates research decisions.

## Phase 1: Design & Contracts

**Status**: ✅ Complete (M1 milestone reached)

### 1. Data Model

**Document Generation Request** (input to pipeline tools):
```python
# Word Document
{
  "title": str,              # Document title
  "author": str,             # Author metadata (optional, defaults to UserValves.default_author)
  "sections": [              # Content sections
    {
      "heading": str,        # Section heading
      "content": str         # Section body text
    }
  ]
}

# Excel Spreadsheet
{
  "title": str,              # Spreadsheet filename base
  "headers": List[str],      # Column headers
  "data": List[List[Any]]    # Row data (must match headers length)
}

# PowerPoint Presentation
{
  "title": str,              # Presentation title
  "author": str,             # Author metadata (optional)
  "slides": [                # Content slides
    {
      "title": str,          # Slide title
      "bullets": List[str]   # Bullet points (or use content for paragraphs)
    }
  ]
}
```

**Document Generation Response** (output from pipeline tools):
```python
{
  "success": bool,           # Operation status
  "file_path": str,          # Absolute path to generated file (if success)
  "filename": str,           # Base filename
  "format": str,             # Document format (DOCX/XLSX/PPTX)
  "size_bytes": int,         # File size (if success)
  "error": str               # Error message (if not success)
}
```

**Admin Valves** (server-wide configuration):
- `OUTPUT_DIR`: Output directory path (default: `/app/pipelines/output`)
- `MAX_FILE_SIZE_MB`: File size limit (default: 10)
- `ENABLE_DOCX/XLSX/PPTX`: Format toggles (default: True)

**User Valves** (per-user configuration):
- `include_timestamp`: Add timestamp suffix to filenames (default: True)
- `default_author`: Default author metadata (default: "BMS Agent")

### 2. API Contracts

**Pipelines Server Endpoints** (provided by OpenWebUI Pipelines):
```
GET  /health              # Health check
GET  /pipelines           # List registered pipelines
POST /pipelines/{id}      # Invoke pipeline function
```

**Pipeline Function Tools** (registered by bms_document_generator.py):
```python
# Tool 1: create_word_document
async def create_word_document(
    title: str,
    sections: List[Dict[str, str]],
    author: Optional[str] = None
) -> Dict[str, Any]

# Tool 2: create_excel_spreadsheet
async def create_excel_spreadsheet(
    title: str,
    headers: List[str],
    data: List[List[Any]]
) -> Dict[str, Any]

# Tool 3: create_presentation
async def create_presentation(
    title: str,
    slides: List[Dict[str, Any]],
    author: Optional[str] = None
) -> Dict[str, Any]
```
